# 节奏小节校对

一个用于校对乐谱小节时值的网页工具（React + TypeScript）。粘贴含拍号与逐小节事件树的 JSON，即可以精确分数逐小节核算应有时值、实际时值与不足/超出量；超出时定位首个越界叶事件的树路径，非法输入逐条指出树路径。

还可提供可选的**参考演奏**（`referenceMeasures`）：两侧分别核算时值，对时值均正确的小节展开为精确分数时间段并比较发声轮廓，不同则定位最早差异区间，并可**按参考修正记谱**——仅切换不一致叶事件的 `note`/`rest` 类型。

## 启动

```bash
docker compose up --build
```

启动后访问 **http://localhost:8080** 即可使用（页面已预置可编辑示例与格式说明）。

> 入口地址与端口：`http://localhost:8080`，端口映射见 `docker-compose.yml`（宿主 8080 → 容器 80）。如需更换端口，修改 `ports` 即可。

## 操作步骤

1. 启动后浏览器打开 **http://localhost:8080**，在左侧「输入 JSON」中粘贴或编辑乐谱。
2. 右侧「校对结果」逐小节展示应有时值、实际时值与差值；提供了 `referenceMeasures` 时还含参考演奏对照。
3. 对**时值不足**的小节，页面按精确分数给出缺口，并在允许休止符范围内生成补全建议（规则见下）。
4. 点击建议旁的「预览建议」，查看将追加到该小节 `events` 末尾的休止符 JSON（同一时刻只能预览一个建议）。
5. 确认无误后点击「应用建议」：休止符按时值降序追加到对应小节的 `events` 末尾，原有事件与另一侧（记谱 / 参考演奏）内容保持不变；输入 JSON 随之更新并自动重新校对。
6. 缺口无法用允许休止符精确组成时，仅显示缺口原值与「不可补足」提示，不提供近似方案。
7. 对**两侧时值均正确但演奏轮廓不同**的小节，对照卡片下方给出「按参考修正记谱」：列出全部拟修改叶路径与前后类型（`note`/`rest`）。
8. 点击「预览修改」查看修改前后的叶事件 JSON，确认后点击「应用修正」：仅切换这些叶的 `type`，自动重新校对；若参考状态在某叶内部变化，则只显示该叶路径与原因，不提供方案。


## 输入格式

```json
{
  "timeSignature": { "numerator": 4, "denominator": 4 },
  "measures": [
    {
      "events": [
        { "type": "note", "denominator": 4, "dot": true },
        { "type": "rest", "denominator": 8 },
        {
          "type": "tuplet",
          "actual": 3,
          "inTimeOf": 2,
          "events": [{ "type": "note", "denominator": 8 }]
        }
      ]
    }
  ],
  "referenceMeasures": [
    {
      "events": [
        { "type": "note", "denominator": 4, "dot": true },
        { "type": "rest", "denominator": 8 },
        {
          "type": "tuplet",
          "actual": 3,
          "inTimeOf": 2,
          "events": [{ "type": "note", "denominator": 8 }]
        }
      ]
    }
  ]
}
```

规则：

- 时值以全音符为 1，`denominator` 表示全音符的几分之一，限 1、2、4、8、16、32（拍号、音符、休止符相同）。
- `dot: true` 表示带一个附点，时值 ×3/2；可省略。
- 连音组内时值之和 × `inTimeOf`/`actual`（占用数/实际数），最多三层嵌套。
- 拍号分子、连音的 `actual` 与 `inTimeOf` 必须为正整数。
- 所有计算基于 BigInt 精确分数，无浮点误差。
- `referenceMeasures` 可选；提供时小节数须与 `measures` 相同，事件结构与校验规则同 `measures`。

## 参考演奏对照

提供 `referenceMeasures` 后逐小节对照：

1. **时值优先**：两侧分别核算时值，任一侧不足或超出时，该小节仅显示时值问题，不做对照。
2. **展开**：两侧时值均正确时，将嵌套连音按沿途倍率（`inTimeOf`/`actual` 的乘积）展开为精确分数时间段，音符视为发声、休止符视为静音。
3. **比较**：合并相邻同状态片段后比较整小节发声区间，等价的事件拆分（如 `1/8 + 1/8` 与 `1/4`）视为一致。
4. **结论**：轮廓不同则显示最早差异区间的起止时刻（以全音符为 1、从小节起点计）、两侧状态（发声/静音）及两侧原事件树路径；相同则标记「演奏轮廓一致」。
5. **修正**：轮廓不同的小节可生成「按参考修正记谱」方案，规则见下节。

## 按参考修正记谱

对两侧时值均正确但发声轮廓不同的小节，可生成仅切换叶事件类型的修正方案：

1. **精确对齐**：两侧叶事件按精确分数展开为时间段（嵌套连音按沿途倍率缩放），逐叶按时间区间与参考状态对齐。
2. **方案条件**：仅当每个不一致的记谱叶事件覆盖的参考状态**恒定**时，生成将该叶 `type` 在 `note`/`rest` 间切换的方案；分母、附点与连音结构保持不变。
3. **不给部分方案**：参考状态在某个记谱叶事件**内部变化**时，显示该叶路径、覆盖区间及参考状态变化明细，不提供任何修改方案。
4. **预览与应用**：页面列出全部拟修改叶路径与前后类型，可预览修改前后的叶事件 JSON；确认后点击「应用修正」，仅更新该小节 `measures` 的对应叶事件，`referenceMeasures` 与其他小节不变，并自动重新校对。
5. **不提供修正的情形**：未提供参考演奏，或任一侧时值不足/超出时，不生成修正方案。

## 不足小节休止符补全

对记谱（`measures`）或参考演奏（`referenceMeasures`）中时值不足的小节，自动给出补全建议：

1. **精确缺口**：缺口 = 应有时值 − 实际时值，全部基于 BigInt 精确分数计算。
2. **允许休止符**：只使用分母为 1、2、4、8、16、32 的普通休止符与单附点休止符（时值 ×3/2），与输入校验规则一致。
3. **最优方案**：在所有能**精确**组成缺口的方案中，取追加**事件数最少**的一个；事件数相同时优先选择较长时值（等价于从最长休止符起计数向量字典序最大），结果按时值降序排列展示。
4. **不可补足**：缺口不能用上述休止符精确组成时（例如连音折算产生的 1/64 缺口），显示缺口原值与不可补足提示，**不给出近似方案**。
5. **预览与应用**：每次只能选中一个建议预览；应用后休止符追加到对应小节 `events` 末尾，更新输入 JSON 并重新校对——原有事件、小节顺序与另一侧内容均不改变。
